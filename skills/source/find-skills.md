## 意图

帮助 AI 在用户需要扩展能力时，从开放生态中快速发现并安装合适的技能。
该技能用于“先找现成能力，再决定是否自建方案”，提升问题解决效率与结果质量。

## 触发方式

当用户出现以下意图时可触发：
- 有没有做 X 的 skill
- 帮我找一个适合 X 的技能
- 这个能力你会不会，能不能扩展
- 我想给 agent 增加某个领域能力
- 如何搜索可用的工作流/模板/工具技能

## 核心行为

AI 在执行该技能时，应先判断“是否已有成熟 skill 可用”，再进入搜索与安装流程。

### 步骤 1

识别用户需求并提炼查询词：
- 将用户目标归纳为 1 到 3 个关键词。
- 明确任务类型（开发、测试、部署、设计、自动化等）。
- 若需求含糊，先给出可搜索的候选方向。

### 步骤 2

优先查找已验证的热门技能：
- 先参考 skills.sh 榜单与官方来源技能。
- 优先考虑安装量较高（如 1K+）且长期活跃的条目。
- 结合来源信誉（例如 Vercel、Anthropic 等官方或知名组织）。

### 步骤 3

使用 Skills CLI 进行搜索与安装：
- 搜索：`npx skills find <query>`
- 安装：`npx skills add <package-or-repo> [--skill <name>]`
- 在安装前说明为何推荐该技能；安装后说明可用能力范围。

### 步骤 4

进行质量与风险检查：
- 检查 GitHub stars、近期活跃度与维护情况。
- 查看公开安全审计结果并提示风险等级。
- 若缺乏高质量候选，明确告知并提供替代实现路径。

## 行为约束

AI 在使用该技能时应遵守以下约束：
- 不把搜索结果数量当作质量保证。
- 不在缺少来源信息时盲目推荐未知包。
- 不忽略用户现有技术栈与约束条件。
- 不把安装步骤当作终点，应补充“安装后如何使用”。

## 最佳实践

- 先给 1 个主推荐，再给 1 到 2 个备选。
- 明确每个候选的适用场景与不适用场景。
- 对同类技能给出对比维度：安装量、维护状态、上手成本。
- 推荐时优先“可立即落地”的技能，而非仅概念性方案。

## 输出格式

建议输出采用以下结构：
1. 需求归类（用户想解决的问题与关键词）
2. 推荐技能清单（主推荐 + 备选，附理由）
3. 安装命令（可直接执行）
4. 使用入口（安装后如何触发与验证）
5. 风险提示（来源、活跃度、安全审计）
